SOC Lab Project

Objective:
The objective of this project is to build a home Security Operations Center (SOC) lab so as to simulate real world attack scenarios, test the detection rules and also to practice the incident response.

Architecture:
The phase of the project consists of and Ubuntu server running the Wazuh All in One deployment (Wazuh-Manager, Wazuh-Indexer and Wazuh-Dashboard)

Phase 1 : SIEM Deployment
In this phase, the Wazuh SIEM was successfully installed and configured.
Steps Taken :
a. Deployed Ubuntu server
b. Configured network bridging to allow external dashboard access.
c. Installed Wazuh using the all in one deployment script.
d. Successfully accessed the Wazuh dashboard.

Phase 2: Windows Endpoint & Agent Deployment
In this phase a Windows 11 Enterprise VM was deployed and connected to the Wazuh SIEM to act as our monitor at the endpoint.
Steps taken:
a. Deployed Windows 11 VM in Virtualbox with Bridged Networking.
b. Downloaded and installed the Wazuh Agent (V4.7.2) on Windows.
c. Registered the agent with the Wazuh-Manager automatically using the agent-auth.exe tool.
d. Verified the successful connection in the Wazuh Dashboard.

Phase 3 : Logging and APT Threat Simulation
In the this phase the Windows endpoint was configured with enhanced and detailed logging, and real world Advanced Persistent Threats (APT) framework was executed to validate the SIEM's detection capabilities.
Steps taken:
a. Downloaded and installed Sysmon (System Monitor) with SwiftOnSecurity configuration file to capture process creation, network connections, and file changes.
b. Modified the Wazuh agent configuration (ossec.conf) to ingest the Microsoft-Windows-Sysmon/Operational event channel.
c. Disabled Windows Defender real time protection in the VM so as to allow for the safe execution of an external attack framework.
d. Downloaded and executed PowerSploit Framework (Invoke-Mimikatz) via an administrative Powershell session to simulate OS credential Dumping (MITRE T1003.001)

Detection & Analysis (Incident Response)
Upon executing the simulation the Wazuh agent successfully forwarded the logs to the Wazuh Manager before massive volume of log temporarily crashed the agent service. A total of 196 alerts were generated. <img width="1365" height="639" alt="alerts new1" src="https://github.com/user-attachments/assets/60a8b341-0689-4f34-a5cb-1f3a586713c9" />

Attack Timeline & Key Alerts Triggered:
By analyzing the log timestamps, the attack timeline was reconstructed. The simulation was executed in two phases, intentionally creating a "Dwell Time" gap (the time an attacker pauses activity before executing the next stage of attack or remains Dormant).

Phase 1 : Initial Access and Escalation
1. 12:59:46 - Initial Access (T1105) : Level 15 alert was triggered for an executable file dropped in folder that is commonly used by malware.
2. 13:01:55 - Privilege Escalation (T1548:002) : Level 12 alert triggered for UAC bypass using FodHelper.exe.
(Paused for around 50 Minutes to review the Dashboard and verify the logs before executing the next stage)

Phase 2 : Credential Dumping and Discovery
1. 13:51:04 - Discovery (T1087) : Level 3 alerts triggered as Mimikatz executed net.exe account discovery commands.
2. 13:51:06 - Credential Access (T1105) : Level 9 alert triggered as the Powershell process created an executable file in the Windows root folder.
3. 13:51:07 - Crash (T1562.001) : Level 3 alert was triggered as the Wazuh agent stopped due to the overwhelming flood of logs generated by the credential dump tool.

Lessons Learned & Future Improvements:
1. Resource Allocation : The log flood that was generated by Mimikatz temporarily crashed the Wazuh agent. In a production environment, increasing agent buffer size or the RAM allocation would prevent this issue.
2. Automated Response : We can implement automated response (SOAR) with tools like Shuffle to automatically isolate the endpoint when the Level 15 alert is triggered.
3. Operational Security : In this project we disabled the Windows Defender to execute the simulation. In future we can implement custom exclusions or utilizing a target attack simulator would be safe operational practice.
4. Future Improvements : We can expand the project in future by including Active Directory to detect lateral movement techniques.
